# TimesFM：Google 的时间序列基础模型

> TimesFM（Time Series Foundation Model）是 Google Research 开发的预训练时间序列基础模型，面向负荷、销量、交通、金融和其他连续时间序列的零样本预测。它的核心思路是使用 decoder-only Transformer，把时间序列切分为 patch，并像预测 token 一样预测后续 patch。
>
> 本文介绍 TimesFM 1.0、2.0、2.5 和 3.0 的主要变化。模型代码、权重和接口会更新，实际使用时应以[官方仓库](https://github.com/google-research/timesfm)和对应模型卡为准。

## 1. 版本总览

| 版本 | 状态 | 参数量 | 最大上下文 | 主要输入与能力 | 常见检查点 |
| --- | --- | ---: | ---: | --- | --- |
| **TimesFM 1.0** | 归档 | 约 200M | 2,048（早期文档也曾以 512 描述基础检查点能力） | 主要是单变量点预测，带可选频率指示器 | `google/timesfm-1.0-200m-pytorch` |
| **TimesFM 2.0** | 归档 | 约 500M | 2,048 | 单变量点预测；实验性分位数头；支持微调和外部回归量接口 | `google/timesfm-2.0-500m-pytorch` |
| **TimesFM 2.5** | 2.x 主力版本 | 约 200M | 16,384 | 更长上下文、可选连续分位数头；可通过 XReg 使用协变量 | `google/timesfm-2.5-200m-pytorch` |
| **TimesFM 3.0** | 当前最新版本 | 以官方模型卡为准 | 以官方模型卡为准 | 原生多变量预测，支持过去和过去—未来协变量 | `google/timesfm-3.0-pytorch` |

版本演进可以概括为：

```text
1.0：单变量点预测
  ↓
2.0：更大模型、更长上下文、微调与实验性概率头
  ↓
2.5：参数更少、上下文大幅扩展、连续分位数预测
  ↓
3.0：原生多变量与灵活协变量，面向更通用的预测任务
```

## 2. TimesFM 的基本架构

TimesFM 的原始论文将它描述为用于时间序列预测的 **decoder-only foundation model**。它不是把数值直接当作自然语言 token，而是先进行缩放和 patch 化，再由 Transformer 根据历史 patch 预测未来 patch。

```text
历史数值序列
      ↓
缩放、切分为 patch、加入时间/频率信息（旧版本）
      ↓
Decoder-only Transformer
      ↓
预测未来 patch 的点值或分位数
      ↓
拼接并还原为原始尺度
```

### 2.1 Patch 表示

假设每个 patch 包含 4 个时间点：

```text
原始序列：x1  x2  x3  x4  x5  x6  x7  x8  x9  x10 x11 x12
Patch：   [x1 x2 x3 x4]    [x5 x6 x7 x8]    [x9 x10 x11 x12]
```

Patch 能减少 Transformer 需要处理的时间位置，同时保留局部变化。预测时，模型会根据历史 patch 逐步产生未来 patch；这与 Chronos-Bolt 的直接多步分位数预测不同。

### 2.2 点预测与概率预测

早期 TimesFM 主要输出点预测。2.0 提供了实验性分位数头，但官方说明这些分位数在预训练后未完成校准。2.5 增加了可选的连续分位数预测头，最长可覆盖 1,000 步预测。

因此，使用分位数输出时应检查预测区间的覆盖率，不能只因为模型返回了 P10/P50/P90 就认为区间已经校准。

## 3. TimesFM 1.0：首个公开版本

TimesFM 1.0 是首个公开的 TimesFM 检查点，参数量约 2 亿。它的定位是通用的单变量零样本预测模型：输入一条历史序列，输出未来的点预测。

主要特点：

- 以单变量预测为主；
- 支持最长约 2,048 个历史位置的模型接口，早期检查点和文档中也出现过 512 的基础上下文限制；
- 可以使用频率指示器帮助模型区分高频、日频、周频等数据；
- 重点是点预测，分位数头属于实验性能力，不能默认视为校准后的概率预测。

TimesFM 1.0 适合用来理解原始模型和复现实验，但新项目通常应优先评估 2.5 或 3.0。

## 4. TimesFM 2.0：更大模型与更长上下文

TimesFM 2.0 于 2024 年底发布，使用约 5 亿参数的检查点。相较 1.0，官方资料强调它在主要基准上有更好的表现，并将最大上下文长度扩展到 2,048 个时间点。

主要变化：

1. **模型容量增大**：从约 200M 增加到约 500M 参数。
2. **长上下文支持**：相比早期 512 点的限制，2.0 的常用接口支持最多 2,048 点上下文。
3. **微调支持**：可以使用自己的时间序列对预训练权重进行任务适配。
4. **外部回归量接口**：可以通过额外的回归量模块使用协变量，但这与 3.0 的原生多变量建模不同。
5. **实验性分位数头**：可以输出多个分位数，但官方明确提示需要自行验证校准效果。

2.0 的代价是显存和内存需求明显高于 1.0。若只是单变量零样本预测，2.5 往往具有更好的资源效率。

## 5. TimesFM 2.5：更小、更长、更实用

TimesFM 2.5 于 2025 年 9 月发布，是 2.x 系列中面向实际使用的重要版本。它将参数量降到约 2 亿，同时把最大上下文扩展到 16K（16,384）时间点。

### 5.1 主要改进

- **参数量降低**：约 200M，而 TimesFM 2.0 约 500M；
- **上下文扩展**：最多约 16,384 个时间点；
- **连续分位数预测**：可选的约 30M 参数 quantile head 支持最长约 1,000 步的连续分位数预测；
- **移除 frequency 指示器**：2.5 的接口不再要求 1.0/2.0 中的 `frequency` 参数；
- **推理实现更丰富**：提供 PyTorch 和 Flax 版本，并通过 XReg 支持协变量。

### 5.2 XReg 协变量支持

2.5 的 XReg 可以在 TimesFM 的基础预测之上使用外部回归量，例如节假日、促销、天气或计划信息。它属于“基础模型 + 外部回归模块”的组合，使用时需要明确哪些协变量在预测时已经可知。

```text
目标序列历史值 → TimesFM 基础预测
已知协变量 ────→ XReg
                   ↓
              组合后的预测结果
```

不要把 XReg 与 3.0 的原生多变量注意力混为一谈：前者是额外的回归模块，后者是模型架构本身支持多通道和协变量。

### 5.3 资源需求

官方 TimesFM 使用说明给出的典型估计是：2.5 权重约 800 MB，CPU 推理通常需要至少约 4 GB RAM，GPU 推理建议至少约 2 GB VRAM；实际需求还会随批量大小、上下文长度、精度和运行时变化。

## 6. TimesFM 3.0：原生多变量与协变量

TimesFM 3.0 是当前最新版本。官方仓库将其定位为支持以下任务的通用模型：

- 单变量预测；
- 多通道、多变量时间序列预测；
- 只有过去值可用的协变量预测；
- 在未来预测区间也已知的动态协变量预测。

这意味着 3.0 可以在同一模型中联合处理多个相关序列，而不必先把它们拆成互不关联的单变量任务。

### 6.1 与 2.5 的核心区别

| 能力 | TimesFM 2.5 | TimesFM 3.0 |
| --- | --- | --- |
| 单变量预测 | 支持 | 支持 |
| 原生多变量预测 | 不是主要能力 | 支持多通道联合预测 |
| 过去协变量 | 通过 XReg 等接口 | 原生支持 |
| 已知未来协变量 | 取决于 XReg 接口 | 原生支持 |
| 上下文长度 | 最长约 16K | 以当前模型卡为准 |
| 适用场景 | 资源受限的单变量/长上下文任务 | 复杂多变量和协变量任务 |

3.0 的架构细节、参数量和完整输入格式应以 `google/timesfm-3.0-pytorch` 模型卡为准，不应把 2.5 的参数和上下文数字直接套用到 3.0。

### 6.2 许可证注意事项

官方仓库目前说明：源代码以及 2.5 及以前的模型权重采用 Apache-2.0；TimesFM 3.0 的预训练权重目前采用单独的非商业许可证，限制商业和生产用途。部署 3.0 前必须阅读当前权重附带的许可证条款，不能只根据代码仓库的 Apache-2.0 判断权重是否可商用。

## 7. 四个版本的对比

| 对比项 | TimesFM 1.0 | TimesFM 2.0 | TimesFM 2.5 | TimesFM 3.0 |
| --- | --- | --- | --- | --- |
| 参数量 | 约 200M | 约 500M | 约 200M | 以模型卡为准 |
| 主要任务 | 单变量点预测 | 单变量点预测 | 单变量、长上下文、可选分位数 | 单变量、多变量、协变量 |
| 最大上下文 | 约 2,048（早期基础检查点可为 512） | 2,048 | 16,384 | 以模型卡为准 |
| 频率参数 | 需要 | 需要 | 移除 | 以接口为准 |
| 概率预测 | 实验性 | 实验性，未校准 | 可选连续分位数头 | 以模型卡为准 |
| 协变量 | 有限 | 外部接口/XReg | XReg | 原生支持 |
| 多变量 | 非原生重点 | 非原生重点 | 非原生重点 | 原生支持 |
| 权重许可 | Apache-2.0 | Apache-2.0 | Apache-2.0 | 当前为非商业限制，需单独核对 |

## 8. 如何选择版本

- **学习原理或复现早期论文**：选择 TimesFM 1.0。
- **需要更大模型或复现 2.0 基准**：选择 TimesFM 2.0，但要准备更多内存和显存。
- **单变量预测、长历史窗口、资源有限或需要分位数**：优先评估 TimesFM 2.5。
- **多个相关序列、过去协变量和已知未来协变量共同参与预测**：评估 TimesFM 3.0，并先确认权重许可证是否满足使用场景。

无论选择哪个版本，都应使用滚动时间切分进行回测，并与季节性朴素法、ARIMA、树模型和任务专用神经网络比较。零样本模型节省了训练成本，但不保证在每个数据集上都优于专门训练的模型。

## 9. 基本使用示例（TimesFM 2.5）

安装 PyTorch 版本（具体安装方式以官方仓库当前说明为准）：

```bash
git clone https://github.com/google-research/timesfm.git
cd timesfm
pip install -e ".[torch]"
```

一个简化的推理示例：

```python
import numpy as np
import timesfm
from timesfm.timesfm_2p5.timesfm_2p5_torch import TimesFM_2p5_200M_torch

model = TimesFM_2p5_200M_torch.from_pretrained(
    "google/timesfm-2.5-200m-pytorch"
)

model.compile(
    timesfm.ForecastConfig(
        max_context=1024,
        max_horizon=128,
        normalize_inputs=True,
        per_core_batch_size=8,
        use_continuous_quantile_head=True,
    )
)

history = [np.array([100.0, 105.0, 110.0, 108.0, 115.0])]
point_forecast, quantile_forecast = model.forecast(
    horizon=3,
    inputs=history,
)
```

> 注意：上面代码中的类名、加载方式和返回值可能随 `timesfm` 包版本变化。请以当前官方 README 和模型卡中的示例为准；如果使用 1.0/2.0，需要按旧接口提供 `frequency`，2.5 则不再使用该参数。

## 10. 评估与部署注意事项

1. **明确预测信息集。** 未来协变量只能使用预测时确实可知的数据，否则会产生数据泄漏。
2. **注意版本接口差异。** 1.0/2.0 与 2.5 的 frequency 参数不同，3.0 的多变量输入也不能按单变量列表直接猜测。
3. **评估概率预测。** 除 MAE、RMSE 外，应检查 pinball loss、区间覆盖率和区间宽度。
4. **处理缺失与异常值。** 长上下文并不能自动修复错误时间戳、重复记录或大段缺失。
5. **固定依赖和权重版本。** 生产环境应锁定 Python 包版本、模型 revision、精度和设备配置。
6. **核对许可证。** 尤其是 TimesFM 3.0，商业或生产部署前必须单独确认当前权重许可。
